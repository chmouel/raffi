A script filter turns any command into a live Raffi search source. When you
type its keyword followed by a space, Raffi runs the command with the rest of
your query and displays the JSON items it prints. The format follows a subset of
[Alfred's Script Filter JSON](https://www.alfredapp.com/help/workflows/inputs/script-filter/json/),
extended with tree indentation, relative timestamps, nested and lazily loaded
children, custom action menus, views, and rich previews.

<Image src={scriptFilterTzScreenshot} alt="Script filter timezone converter example" width={800} />

## Quick start

This entry wires [batz](https://github.com/chmouel/batzconverter) to the `tz`
keyword:

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Timezones"
      keyword: "tz"
      command: "batz"
      args: ["-j"]
      icon: "clock"
```

Type `tz new york` to run `batz -j "new york"`. Raffi displays the returned
items and copies the selected value when you press Enter.

Typing `tz` without a trailing space keeps you in the main list, where Raffi
offers a row to enter the filter with Enter or Tab. Once inside the filter,
Raffi re-runs the command whenever the query text changes.

## Configuration

Define script filters as a list under `addons.script_filters`, one entry per
keyword.

**`name`** `string` (required)

Display name shown while the command runs. Also identifies the filter in
`general.main_view`, `general.fallbacks`, and
`-o addons.script_filters.<name>.<key>=...`.

**`keyword`** `string` (required)

Trigger word for the filter. You enter the filter by typing the keyword
followed by a space. If two sources share a keyword, the first script filter
wins; script filters take precedence over text snippets, web searches, and
built-in addons.

**`command`** `string` (required)

Executable to run. Raffi invokes it directly without a shell, passing `args`
followed by the query text as the final argument (an empty string if nothing
follows the space). Leading `~/` and `${VAR}` references are expanded.

**`args`** `list of strings` (default: `[]`)

Static arguments passed before the query. Values are passed verbatim, so write
full paths instead of `~`.

**`icon`** `string`

Fallback icon theme name or image path for items that omit `icon`. Leading
`~/` and `${VAR}` references are expanded.

**`action`** `string` (default: `copy`)

Action run on Enter: `copy`, `insert`, or a shell command. Leading `~/` and
`${VAR}` references are expanded when Raffi loads the config, so reference
item-exported environment variables as `$VAR` without braces.

**`secondary_action`** `string` (default: same as `action`)

Action run on Ctrl+Enter, using the same syntax and expansion rules as
`action`.

**`actions`** `list of objects` (default: `[]`)

Extra entries appended to every valid row's action menu after the row's own
[custom actions](#custom-actions). Each entry takes a `title` and an `action`.

**`env`** `map of strings` (default: `{}`)

Environment variables exported to the script during list,
[preview](#dynamic-previews), and [lazy children](#nested-lists-and-lazy-children)
runs. They are not exported to actions.

**`min_query_length`** `integer` (default: `0`)

Minimum number of characters required after the keyword before Raffi runs the
command. Until then, Raffi displays a prompt showing how many characters
remain.

**`sort_by_usage`** `boolean` (default: follows the script's `sort`)

Controls [usage-based sorting](#sorting-by-usage). When unset, Raffi sorts by
usage only if the script prints `"sort": "usage"`. Set to `true` to always
lift picked rows, or `false` to preserve script order and stop recording picks.

**`cache_seconds`** `integer`

Enables the private [stale-while-revalidate cache](#caching) and sets the
default freshness window in seconds. Omitting it disables caching completely.

**`cache_max_seconds`** `integer`

Upper bound in seconds when a script requests a longer freshness window via
`"cache": {"seconds": N}`. Never enables caching on its own and never lowers
`cache_seconds`.

**`warm_queries`** `list of strings` (default: `[]`)

Queries refreshed in the background by `raffi --server`.

**`warm_interval_seconds`** `integer` (default: `cache_seconds`)

Minimum interval between background refreshes for `warm_queries`.

**`dynamic_preview`** `boolean` (default: `true`)

Re-runs the command with `RAFFI_PREVIEW=1` for the selected row when the
preview pane is open. Set to `false` to rely strictly on each item's static
`preview` field.

**`close_on_action`** `boolean` (default: `true`)

Closes Raffi after running an action. Falls back to `general.close_on_action`
when unset. The `insert` action always closes Raffi.

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Timezones"
      keyword: "tz"
      command: "batz"
      args: ["-j"]
      icon: "clock"
      action: "copy"
      secondary_action: 'notify-send "$RAFFI_VALUE"'
      env:
        TZ_FORMAT: "short"
      min_query_length: 2
      dynamic_preview: false
      close_on_action: false
```

### Including a filter in the main list

Add `script_filters."<name>"` to
[`general.main_view`](../../configuration/main-list/#choosing-what-it-shows) to
run the filter without typing its keyword. Raffi displays its first five
results in the main list after you pause typing, provided the query meets
`min_query_length`. You can also add a filter to
[`general.fallbacks`](../../configuration/main-list/#fallbacks) to show it at
the bottom of every search.

## Actions and navigation

| Key | Behavior |
|---|---|
| Enter | Open a row's children, or run `action` on a leaf row |
| Ctrl+Enter | Run `secondary_action`, or `action` if unset |
| Right / right-click | Open the row's action menu |
| Up / Down | Move selection |
| Ctrl+Tab / Ctrl+Shift+Tab | Switch between [views](#views) |
| Ctrl+R | Refresh the current list with `RAFFI_REFRESH=1` |
| Escape | Return to the parent list, or close Raffi at the top level |

Actions operate on the item's `arg`, falling back to `title` if `arg` is
absent. Three action forms are supported:

- `copy` (the default) copies the value with `wl-copy`, `xclip`, or `xsel`.
- `insert` closes Raffi and types the value into the focused window with
  `wtype` or `ydotool`.
- Any other string runs through `sh -c` with `{value}` substituted.

Raffi also exports the selected value as `$RAFFI_VALUE`, along with every key
from the item's `variables` map:

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Bookmarks"
      keyword: "bm"
      command: "my-bookmark-script"
      args: ["--json"]
      icon: "bookmark"
      action: "copy"
      secondary_action: 'xdg-open "$RAFFI_VALUE"'
```

Because `{value}` is interpolated as raw text before the shell parses the
command, quotes or `$(...)` inside an item's value can execute arbitrary shell
syntax. Quote `"$RAFFI_VALUE"` instead whenever item data comes from an
external source.

### Custom actions

Press Right at the end of the query, or right-click any valid row, to open its
action menu. The menu lists Enter, Ctrl+Enter, the row's own `actions`, and
finally the filter's configured `actions`.

<Image src={scriptFilterActionsScreenshot} alt="Action menu of a repository row listing its pull requests, issues and releases" width={800} />

```json
{
  "title": "repo",
  "arg": "https://github.com/owner/repo",
  "variables": { "REPO_SSH": "git@github.com:owner/repo.git" },
  "actions": [
    { "title": "Pull requests", "arg": "https://github.com/owner/repo/pulls" },
    { "title": "Copy SSH URL", "arg": "git@github.com:owner/repo.git", "action": "copy" },
    { "title": "Clone", "action": "git clone \"$REPO_SSH\" ~/src/repo" }
  ]
}
```

Each entry accepts four fields:

- `title` sets the menu label and is matched when you type inside the menu.
- `arg` overrides `{value}` and `$RAFFI_VALUE` for this action; defaults to
  the row's value.
- `variables` merges on top of the row's `variables`.
- `action` accepts `copy`, `insert`, or a shell command; defaults to the
  filter's `action`.
- `refresh: true` keeps Raffi open and runs the filter again for the same
  query once the action finished, skipping the cached list but not the
  script's own caches. Use it for an entry that changes the rows, such as
  hiding one: the list updates on the spot instead of closing Raffi.

Running a menu action respects `close_on_action`, unless the entry sets
`refresh`, which keeps the window open. Menu actions never open the row's
children, and skip recording a recent pick if the row has children or sets
`refresh`, since the row it acted on is gone or back. Rows with `valid: false`
have no action menu. If a background refresh replaces the row while the menu is
open, choosing an entry does nothing.

<Aside type="caution">
Item-defined `action` commands always run through `sh -c`, regardless of the
filter's own `action`. Keep untrusted text out of `action` strings and read
quoted `"$VAR"` environment variables instead of interpolating `{value}`. Note
that cached results (`cache_seconds`) store row actions as well.
</Aside>

To add the same menu entries to every row in a filter, configure `actions` in
`raffi.yaml`:

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Repositories"
      keyword: "repo"
      command: "~/.config/raffi/scripts/github/repos.py"
      action: "xdg-open {value}"
      actions:
        - title: "Clone"
          action: 'git clone "$REPO_SSH" ~/src/"$REPO_NAME"'
```

### Nested lists and lazy children

A row can open a nested list on Enter instead of running an action. Raffi
supports two ways to supply child rows:

1. Inline `children`: embed a list of child items directly on the parent row.
   Use this when the child data is already in memory (such as contact fields or
   local search hits).
2. On-demand `children_lazy: true`: defer loading until the user presses Enter
   on the row. Use this for API-backed lists where fetching children upfront
   for every row would be slow or wasteful.

When you open a child list, Raffi clears the search bar so typing filters the
current children locally by `title`, `subtitle`, or `arg` without re-running
the script. Press Escape to return to the parent list with its previous query
and selection intact. Child items can themselves have inline or lazy children.

When a row has `children_lazy: true` (and no inline `children`), pressing Enter
re-runs the filter command with `RAFFI_CHILDREN=1` and the same environment
contract as [dynamic previews](#dynamic-previews): `RAFFI_VALUE`,
`RAFFI_TITLE`, `RAFFI_QUERY`, the filter's `env`, the active view's
`variables`, the row's `variables`, and theme variables. The script prints a
standard `{"items": [...]}` payload.

- Raffi caches the expanded list in memory for the session, or for the
  response's top-level `cache` duration (`"cache": 0` disables caching).
- Pressing Ctrl+R inside an inline child list exits navigation and refreshes
  the root query. Pressing Ctrl+R inside a lazily loaded child list stays in
  that list and re-runs `RAFFI_CHILDREN=1` with `RAFFI_REFRESH=1`.
- Pressing Escape while a lazy load is in flight cancels it and restores the
  parent list.
- Empty responses and errors display a non-selectable status row (`No items` or
  `Failed to load: ...`) so Escape and Ctrl+R remain available.
- Lazy children runs are killed after 10 seconds.

## Output format

Your script writes a JSON object containing an `items` array to standard
output. Optional top-level keys are [`cache`](#script-controlled-freshness),
[`views`](#views), `view`, and [`sort`](#sorting-by-usage). Standard error is
ignored. If the command exits non-zero or prints invalid JSON, Raffi shows an
empty list, so test scripts directly in a terminal first (for example,
`my-script -j "test query"`).

A minimal script:

```python my-filter.py
#!/usr/bin/env python3
import json
import sys

query = sys.argv[1] if len(sys.argv) > 1 else ""

print(json.dumps({"items": [
    {
        "title": f"Result for: {query}",
        "subtitle": "This is a subtitle",
        "arg": f"https://example.com/search?q={query}",
        "icon": {"path": "/usr/share/icons/search.png"},
    }
]}))
```

```yaml raffi.yaml
addons:
  script_filters:
    - name: "My Filter"
      keyword: "mf"
      command: "~/bin/my-filter.py"
      action: 'xdg-open "$RAFFI_VALUE"'
```

A fuller response with sorting and nested children:

```json
{
  "sort": "usage",
  "items": [
    {
      "title": "Alice",
      "subtitle": "Engineering",
      "children": [
        { "title": "Email", "arg": "alice@example.com" },
        { "title": "Phone", "arg": "+1 555 0100" }
      ]
    },
    {
      "title": "Pull requests",
      "arg": "https://github.com/owner/repo/pulls",
      "variables": { "REPO_NAME": "owner/repo", "LIVE_PATH": "pulls" },
      "children_lazy": true
    }
  ]
}
```

Raffi preserves the order your script prints unless usage sorting is active.
Filtering the top-level list is the script's responsibility.

### Item fields

**`title`** `string` (required)

Primary row text. Supports [ANSI colours](#colours).

**`subtitle`** `string`

Secondary line under the title. Supports ANSI colours.

**`arg`** `string`

Value passed to actions and exported as `RAFFI_VALUE`. Falls back to `title`
when omitted.

**`icon.path`** `string`

Absolute path to a PNG or SVG icon. Falls back to the filter's `icon`.

**`time`** `string`, `integer`, or `object`

Timestamp rendered as a live relative age after the subtitle (such as
`pushed 3h ago`) and as a formatted local date in the preview pane. Computing
the relative text at draw time keeps cached lists accurate without baking stale
ages into `subtitle`.

```json
{ "title": "raffi", "subtitle": "Rust", "time": "2026-11-19T05:10:04Z" }
{ "title": "raffi", "time": 1763529004 }
{ "title": "raffi", "time": { "at": "2026-11-19T05:10:04Z", "label": "pushed" } }
```

`at` accepts an RFC 3339 string or integer Unix seconds. The optional `label`
prefixes the relative age (`pushed 3h ago`) and titles the preview metadata
row; control characters are stripped and labels are truncated to 32
characters. Invalid timestamps or dates more than a century away are ignored
without failing the list. Times within a minute read `just now`, future times
read `in 2d`, and durations round down to whole minutes, hours, days (30-day
months), and years. Raffi redraws visible `time` rows every 30 seconds.

**`children`** `list of items`

Inline nested items opened on Enter or click. Child items support the full set
of item fields.

**`children_lazy`** `boolean` (default: `false`)

Defers loading child items until the row is expanded, triggering a
`RAFFI_CHILDREN=1` run. Ignored if `children` is present.

**`actions`** `list of objects`

Row-specific entries for the action menu. See [Custom actions](#custom-actions).

**`valid`** `boolean` (default: `true`)

Set to `false` for non-actionable rows such as headings or status messages.
They remain focusable for reading previews, but ignore Enter, Ctrl+Enter,
clicks, recent-pick tracking, and `--select-1`.

**`indent`** `integer` (default: `0`)

Tree nesting depth (Raffi extension, ignored by Alfred). See
[Tree results](#tree-results).

**`preview`** `string` or `object`

Static preview content: ANSI-coloured text, a local file or image path, or a
[preview object](#preview-object). Set `"dynamic": false` on a preview object
to exempt that row from [dynamic preview](#dynamic-previews) runs.

**`variables`** `map of strings`

Key-value pairs exported as environment variables to dynamic preview runs,
lazy children runs, and shell actions.

**`quicklookurl`** `string`

Alfred QuickLook URL or local file path (`file://`, `/path`, or `~/path`).
Local files and images render in the preview pane.

**`text.largetype`** `string`

Fallback preview text shown when `preview` is omitted.

**`text.copy`** `string`

Alfred copy text, shown in the preview pane.

### Colours

Titles, subtitles, and preview text support 16-colour, 256-colour, and 24-bit
ANSI SGR sequences, plus bold, dim, italic, and underline. The 16 standard
colours map to your [theme's terminal palette](../themes/#terminal-colours).
Cursor movement, terminal hyperlinks, and other non-colour escape sequences are
stripped, and tabs expand to 8 columns, so output from tools like `bat` or
`eza` renders cleanly.

```json
{
  "items": [
    {
      "title": "\u001b[32mSuccess\u001b[0m",
      "subtitle": "\u001b[90mCompleted at 14:30\u001b[0m"
    }
  ]
}
```

### Tree results

Setting `indent` shifts rows right by level and draws vertical and branch
connector guides, suitable for hierarchies like the [Herdr](#herdr-sessions)
workspace tree:

```json
{
  "items": [
    { "title": "raffi [working]", "subtitle": "1 tab · 2 panes", "arg": "w1", "indent": 0 },
    { "title": "Feature [working]", "subtitle": "copilot, shell", "arg": "w1:t1", "indent": 1 },
    { "title": "copilot [working] - raffi", "arg": "w1:p1", "indent": 2 },
    { "title": "shell - raffi", "arg": "w1:p2", "indent": 2 }
  ]
}
```

Emit parents before their children and keep each subtree contiguous. Each row
attaches to the nearest preceding row with a smaller `indent`. Skipped levels
do not synthesize placeholder rows, and orphaned rows keep their indentation
without drawing a branch. Visual indentation caps at ten levels while
preserving parent-child relationships; overlapping connectors beyond that depth
are omitted. Guides span only visible rows and stop at source boundaries.

### Views

Scripts that offer multiple perspectives on their data (such as GitHub pull
request categories or Herdr workspace vs. status views) can declare a top-level
`views` array. Ctrl+Tab and Ctrl+Shift+Tab cycle through them while preserving
your typed query, and the footer shows the active view.

```json
{
  "views": [
    { "id": "open", "title": "Open issues" },
    { "id": "all", "title": "All issues", "variables": { "SHOW_ALL": "1" } }
  ],
  "view": "open",
  "items": []
}
```

Each view defines an `id`, a footer `title` (defaults to `id`), and optional
`variables` overlaid onto the filter's `env`. On the initial run, Raffi calls
the script without `RAFFI_VIEW` and reads `view` (or the first entry in
`views`) as the default. After switching views, Raffi re-runs the command with
`RAFFI_VIEW=<id>` and the view's `variables` exported; dynamic preview and lazy
children runs inherit them too. Returning to the default view omits
`RAFFI_VIEW` again.

Each view is cached separately, and `raffi --server` warms `warm_queries`
across every declared view (up to 16 besides the default).

## Dynamic previews

When the preview pane is open (Ctrl+P) and `dynamic_preview` is enabled, Raffi
re-runs the filter command for the selected row after you stop moving through
the list. The command receives the same `args` and query as a list run, plus
the filter's `env`, the active view's `variables`, the item's `variables`, and
these protocol variables:

| Variable | Value |
|---|---|
| `RAFFI_PREVIEW` | `1` |
| `RAFFI_VALUE` | Item's `arg`, or its `title` |
| `RAFFI_TITLE` | Item's `title` with ANSI codes stripped |
| `RAFFI_QUERY` | Query text after the keyword |
| `RAFFI_PREVIEW_WIDTH`, `RAFFI_PREVIEW_HEIGHT` | Preview pane dimensions in pixels |
| `RAFFI_THEME`, `RAFFI_THEME_MODE`, `RAFFI_THEME_FG`, ... | Active theme values, see [Terminal Colours](../themes/#terminal-colours) |

Preview runs time out after 3 seconds and cap stdout at 8 MiB. Check
`RAFFI_PREVIEW` at the top of your script before running list logic:

```python
import json
import os

if os.environ.get("RAFFI_PREVIEW") == "1":
    value = os.environ["RAFFI_VALUE"]
    print(json.dumps({"title": value, "text": f"Details for {value}"}))
    raise SystemExit
```

<Aside type="caution">
Because previews re-invoke the filter command, any script with side effects
must check `RAFFI_PREVIEW` first or disable dynamic previews with
`dynamic_preview: false`.
</Aside>

Scripts that do not implement `RAFFI_PREVIEW` require no changes. Raffi probes
a filter once per session, waiting for that first preview run before starting
another. Any JSON object without an `items` key counts as a preview (`{}` is an
empty preview). If the probe fails, times out, prints a normal `{"items": ...}`
list, or prints non-JSON output, Raffi disables dynamic previews for that
filter for the rest of the session and falls back to static `preview` fields.

Once a filter has returned a preview object, later failures (non-zero exit,
timeout, or malformed preview fields) keep the previous preview visible, add an
error row under `Preview`, and retry the next time that row is selected.

### Preview object

Every field is optional:

```json
{
  "title": "claude [working]",
  "subtitle": "project-a",
  "badge": "Herdr",
  "icon": "utilities-terminal",
  "text": "\u001b[32mANSI text\u001b[0m",
  "image": "/tmp/shot.png",
  "sections": [
    { "type": "text", "heading": "Output", "content": "..." },
    { "type": "image", "base64": "iVBORw0KGgo..." },
    { "type": "file", "path": "~/notes.md" }
  ],
  "metadata": [["Status", "working"], ["Directory", "/home/me/project-a"]],
  "refresh": 2
}
```

- `title`, `subtitle`, and `badge` replace the preview header.
- `icon` accepts an icon theme name, image path, or emoji.
- `text` renders body text with 16, 256, and 24-bit ANSI colours.
- `image` accepts a local path, `{"path": "..."}`, or `{"base64": "..."}`
  (raw base64 or a `data:image/...;base64,` URL). Size generated images with
  `RAFFI_PREVIEW_WIDTH` and `RAFFI_PREVIEW_HEIGHT`.
- `sections` renders an ordered sequence of blocks: `text` (`content` and
  optional `heading`), `image` (`path` or `base64`), and `file` (`path`,
  rendered with the file browser viewer for text, images, and directories).
  Setting `sections` overrides `text` and `image`; an empty list clears the
  body. Without `sections`, `image` appears above `text`. Omitting all three
  preserves the item's static body while updating header and metadata.
- `metadata` adds `[label, value]` rows above Raffi's Enter and Ctrl+Enter
  action rows.
- `refresh` re-runs the preview every N seconds while the row stays selected
  (clamped to `0.5`..`3600`). `file` sections re-read from disk on each tick.

The same JSON structure works as an item's static `preview` field, where
`refresh` is ignored and `"dynamic": false` opts the row out of dynamic
previews.

## Caching

Filters that talk to slow APIs can opt into a private stale-while-revalidate
cache by setting `cache_seconds`. Raffi displays the last cached result
immediately while refreshing in the background. Without `cache_seconds`,
nothing is cached.

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Pull Requests"
      keyword: "pr"
      command: "~/.config/raffi/scripts/github/pr.py"
      icon: "github"
      cache_seconds: 300
      warm_queries: [""]
      warm_interval_seconds: 300
```

When [`raffi --server`](../../reference/cli-options/#cache-management) is
running, it refreshes each entry in `warm_queries` across all declared views
once a snapshot outlives its freshness window (and never more often than
`warm_interval_seconds`). Each snapshot is scheduled from its timestamp on disk
with light jitter, so restarting the server does not re-fetch fresh data.
Background runs time out after 60 seconds, and at most one runs per list at a
time. Failed refreshes keep the last good snapshot and retry with exponential
backoff from 1 minute up to 1 hour.

Press Ctrl+R to bypass the cache and run the script with `RAFFI_REFRESH=1`
(which the bundled GitHub scripts use to skip `gh`'s own cache). Press F5 when
`raffi --server` is running to trigger that refresh in the server immediately.

Cached lists and previews live under `$XDG_CACHE_HOME/raffi/script-filters/`,
keyed by command, arguments, environment, view, and query. Run
`raffi --refresh-cache` to clear them.

### Script-controlled freshness

A script can override its cache duration with a top-level `cache` field (either
an object or a bare integer):

```json
{ "cache": { "seconds": 86400, "warm": ["review", "assigned"] }, "items": [] }
```

Your config still bounds what the script can ask for:

| Script `cache.seconds` | Effective freshness |
|---|---|
| Omitted | `cache_seconds` |
| Lower than `cache_seconds` | Script's value |
| Higher than `cache_seconds` | Script's value, capped at `cache_max_seconds` and 7 days |
| `0` | Not stored; treated as a failed refresh if cached rows exist |

```yaml raffi.yaml
      cache_seconds: 300
      cache_max_seconds: 86400
```

A script cannot turn caching on when `cache_seconds` is unset. Bounds are
checked on read, so lowering `cache_max_seconds` applies to existing snapshots
immediately.

Returning `"seconds": 0` protects cached lists from transient errors: Raffi
keeps showing the cached rows, marks the footer with
`cached 3h ago · refresh failed`, and hides error rows in the main view. If no
snapshot exists yet, Raffi displays the returned error rows without saving
them.

The optional `warm` array lets a warmed query nominate up to four additional
queries (at most 64 characters each, without control characters) for
`raffi --server` to keep warm in every view. Server warming still starts strictly
from your configured `warm_queries`; extra queries are not followed
recursively, and any query dropped by a later refresh stops being warmed.

## Sorting by usage

Raffi can float previously picked rows to the top of a filter (most recently
picked first) while leaving untouched rows in the script's original order.

Usage sorting is off by default so time-ordered lists (such as pull requests or
agent statuses) stay in order. A script opts in with a top-level `sort` key:

```json
{ "sort": "usage", "items": [] }
```

Override a script's preference per filter in `raffi.yaml`:

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Timezones"
      keyword: "tz"
      command: "batz"
      args: ["-j"]
      sort_by_usage: true
    - name: "Review requests"
      keyword: "prr"
      command: "~/.config/raffi/scripts/github/pr.py"
      sort_by_usage: false
```

- Picking a row inside a `children` or `children_lazy` list also credits its
  parent row.
- Indented [tree lists](#tree-results), rows with `valid: false`, and rows
  without an `arg` are never reordered.
- Main-view script filter results keep the script's order, though picks made
  from the main view still count toward usage.
- Picks are recorded whenever `sort_by_usage` is not `false` and stored in
  `$XDG_CACHE_HOME/raffi/script-filters.cache`, keyed by filter `name` and row
  `arg`.

## Bundled scripts

### Google Contacts

<Image src={scriptFilterContactsScreenshot} alt="Contact fields with the first field selected and the child search cleared" width={800} />

[`scripts/google-contacts/contacts.py`](https://github.com/chmouel/raffi/blob/main/scripts/google-contacts/contacts.py)
searches your Google Contacts and puts each contact's email addresses, phone
numbers, and details into inline `children`. Press Enter on a contact to open
its fields, Enter on a field to copy it, and Escape to return.

Install the script:

```bash
mkdir -p ~/.config/raffi/scripts/google-contacts
cp scripts/google-contacts/contacts.py ~/.config/raffi/scripts/google-contacts/contacts.py
chmod +x ~/.config/raffi/scripts/google-contacts/contacts.py
```

Enable the People API in a Google Cloud project, create a Desktop app OAuth
client, store its JSON in `pass` (default `google/raffi-contacts`), and run:

```bash
~/.config/raffi/scripts/google-contacts/contacts.py --authorize --pass-entry google/raffi-contacts
```

This opens browser consent for read-only contacts access and writes the refresh
token back into that `pass` entry. Use `GOOGLE_CONTACTS_PASS_ENTRY` in `env` or
`args: ["--pass-entry", "..."]` to select another entry.

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Google Contacts"
      keyword: "contacts"
      command: "~/.config/raffi/scripts/google-contacts/contacts.py"
      icon: "contact-new"
      action: "copy"
      close_on_action: false
      dynamic_preview: false
```

Contacts and photos are cached per `pass` entry under
`$XDG_CACHE_HOME/raffi/google-contacts/<entry-hash>/`. Contact data stays fresh
for five minutes; Ctrl+R refreshes from Google while keeping cached rows on API
errors. Missing photos download in a background worker (capped at 30 seconds
per run) and appear on subsequent runs.

### GitHub pull requests

<Image src={scriptFilterPrScreenshot} alt="GitHub PR browser" width={800} />

[`scripts/github/pr.py`](https://github.com/chmouel/raffi/blob/main/scripts/github/pr.py)
lists open pull requests with CI status, review decision, merge conflicts,
unresolved threads, and diff size using the [GitHub CLI](https://cli.github.com).
Both GitHub scripts import `ghcommon.py`, so keep it in the same directory:

```bash
mkdir -p ~/.config/raffi/scripts/github
cp scripts/github/pr.py scripts/github/ghcommon.py ~/.config/raffi/scripts/github/
chmod +x ~/.config/raffi/scripts/github/pr.py
```

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Pull Requests"
      keyword: "pr"
      command: "~/.config/raffi/scripts/github/pr.py"
      icon: "github"
      action: 'xdg-open "$RAFFI_VALUE"'
      secondary_action: "copy"
```

```text
pr                   your open pull requests across all repositories
pr review            pull requests waiting for your review (also: assigned, involved)
pr owner/repo login  open pull requests of owner/repo matching "login"
```

Ctrl+Tab switches between your pull requests, review requests, assigned, and
involved without clearing your query. Results spanning multiple owners group
under non-selectable owner headings; single-owner or `owner/repo` lists stay
flat.

Pass `args: ["--repo", "owner/repo"]` to dedicate a keyword to one repository,
and set `ALIAS_<name>` variables in `env` for short repository aliases. Each
row exports `PR_URL`, `PR_REPO`, `PR_NUMBER`, and `PR_BRANCH`.

Owner or author avatars are cached under `~/.cache/raffi/github-avatars/`. The
dynamic preview renders branches, reviewer verdicts, merge state, unresolved
threads, CI checks, linked issues, coloured markdown description, recent human
comments, and changed files, refreshing every 20 seconds while checks are still
running. See the
[GitHub scripts README](https://github.com/chmouel/raffi/blob/main/scripts/github/README.md)
for all options.

### GitHub repositories

[`scripts/github/repos.py`](https://github.com/chmouel/raffi/blob/main/scripts/github/repos.py)
lists repositories across your GitHub account and any configured organizations
using the [GitHub CLI](https://cli.github.com). Keep `ghcommon.py` alongside
it:

```bash
mkdir -p ~/.config/raffi/scripts/github
cp scripts/github/repos.py scripts/github/ghcommon.py ~/.config/raffi/scripts/github/
chmod +x ~/.config/raffi/scripts/github/repos.py
```

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Repositories"
      keyword: "repo"
      command: "~/.config/raffi/scripts/github/repos.py"
      args: ["--owners", "me,acme", "--pages", "pulls,issues,releases,actions"]
      env:
        ALIAS_a: acme
      icon: "github"
      action: 'xdg-open "$RAFFI_VALUE"'
      secondary_action: "copy"
      cache_seconds: 86400
      warm_queries: [""]
```

```text
repo                    all --owners accounts mixed, most recently pushed first
repo acme               repositories of an account from --owners
repo acme api           same, filtered by "api"
repo owner/repo         open that repository directly
```

The first word selects an account from `--owners` or an alias (`me` resolves to
the logged-in `gh` user; `ALIAS_<name>` defines custom aliases). Pass
`--any-owner` to allow querying any GitHub account. Configured `--owners`
accounts become Ctrl+Tab views; with more than one, the default `All` view
merges them by last push, labels each row with its owner, and places forks
after source repositories. Remaining words match repository name, initials
(`a gs` finds `go-server`), description, topics, language, and flags.

Rows export `REPO_URL`, `REPO_OWNER`, `REPO_NAME`, `REPO_SSH`, and `REPO_CLONE`,
and the script prints `"sort": "usage"` (disable with `--no-usage-sort` or
`USAGE_SORT=0`). The final row opens the account itself.

Page options control what Enter and the action menu open:

- `--path <page>` makes Enter open a specific page (such as `pulls` or
  `releases`) instead of the repository root.
- `--pages pulls,issues,releases` makes Enter open a child list of those pages
  under the repository.
- `--actions pulls,issues,releases` puts pages in the row's action menu
  instead, except `pulls` and `issues`, which remain live menus.

When `pulls` or `issues` is enabled (and `--no-live` / `LIVE=0` is not set),
each entry sets `children_lazy: true`. Pressing Enter runs `repos.py` with
`RAFFI_CHILDREN=1` to fetch that repository's open pull requests or issues on
demand, newest updated first, followed by an `All … on GitHub` link. Pull
request rows export `PR_URL`, `PR_REPO`, `PR_NUMBER`, and `PR_BRANCH`; issue
rows export `ISSUE_URL`, `ISSUE_REPO`, and `ISSUE_NUMBER`. Raffi caches the
expanded list for `CACHE_LIVE` (default `10m`), Ctrl+R inside the list fetches
live data, and `--live-items` (default 20) sets how many rows to request.

#### Hiding repositories

Right on a repository row opens its action menu, where the last entry, `Hide
forever`, takes the repository out of every list of every account view. The row
disappears on the spot and Raffi stays open: the entry marks itself `refresh`,
so the filter runs again for the query on screen. Typing `owner/repo` still
opens a hidden repository: a full name is not a listing.

Hidden names are kept per GitHub host in
`~/.local/state/raffi/github-hidden.json`, or under `$XDG_STATE_HOME` when it
is set, outside the caches: `rm -rf ~/.cache/raffi` does not bring them back.

`repo --show-hidden` lists what is hidden instead, most recently hidden first,
typed text filtering that list. Each row opens the repository on Enter, and its
action menu leads with `Unhide`. Give it a keyword of its own to keep the list
one word away:

```yaml
    - name: "Hidden repositories"
      keyword: "rhidden"
      command: "~/.config/raffi/scripts/github/repos.py"
      args: ["--show-hidden"]
      icon: "github"
      action: "xdg-open {value}"
      secondary_action: "copy"
```

Pass `--no-hide`, or set `HIDE=0` in the entry's `env`, to leave `Hide forever`
out of the menus, and `SHOW_HIDDEN=1` for the hidden list.

Because `gh` caches repository pages locally, warm queries answer in roughly
100 to 130 ms and typed filters make no network requests. See the
[GitHub scripts README](https://github.com/chmouel/raffi/blob/main/scripts/github/README.md#repositories)
for all settings.

### Web search with autocomplete

[`scripts/search/search.py`](https://github.com/chmouel/raffi/blob/main/scripts/search/search.py)
fetches DuckDuckGo autocomplete suggestions (no API key needed) and opens your
selection in `google`, `duckduckgo`, `bing`, or `brave`:

```bash
mkdir -p ~/.config/raffi/scripts/search
cp scripts/search/search.py ~/.config/raffi/scripts/search/search.py
chmod +x ~/.config/raffi/scripts/search/search.py
```

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Search DuckDuckGo"
      keyword: "ddg"
      command: "~/.config/raffi/scripts/search/search.py"
      args: ["duckduckgo"]
      icon: "web-browser"
      action: 'xdg-open "$RAFFI_VALUE"'
      secondary_action: "copy"

    - name: "Search Google"
      keyword: "sg"
      command: "~/.config/raffi/scripts/search/search.py"
      args: ["google"]
      icon: "google"
      action: 'xdg-open "$RAFFI_VALUE"'
      secondary_action: "copy"
```

The first row searches your exact query; suggestions follow below. The preview
pane displays DuckDuckGo Instant Answers (summary, source link, and image) when
available. On a network error or timeout, the script falls back to the raw
query row. Use the built-in [`web_searches`](../web-search/) addon when you
want direct URL templates without live suggestions.

### Herdr sessions

The [Herdr script filter](https://github.com/chmouel/raffi/tree/main/scripts/herdr)
displays a [Herdr](https://herdr.dev) session as an indented
[tree](#tree-results) of workspaces, tabs, and panes. Single-pane tabs collapse
into one row with their terminal preview attached; split tabs list their panes
underneath. Queries match tab and pane details while preserving matching
ancestors.

<Image src={herdrTreeScreenshot} alt="Herdr demo workspace tree with connected session and pane rows and the selected split session's details" width={800} />

Copy both the script and its `icons` directory (including license notices when
upgrading):

```bash
mkdir -p ~/.config/raffi/scripts/herdr
cp scripts/herdr/herdr_filter.py ~/.config/raffi/scripts/herdr/herdr_filter.py
cp -R scripts/herdr/icons ~/.config/raffi/scripts/herdr/
chmod +x ~/.config/raffi/scripts/herdr/herdr_filter.py
```

Each row exports `HERDR_KIND` (`workspace`, `tab`, `agent`, or `pane`) and
`HERDR_FOCUS`:

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Herdr"
      keyword: "herdr"
      command: "~/.config/raffi/scripts/herdr/herdr_filter.py"
      icon: "utilities-terminal"
      env:
        HERDR_ICON_SET: color
      action: >-
        case "$HERDR_KIND" in
          workspace) herdr workspace focus "$HERDR_FOCUS" ;;
          tab) herdr tab focus "$HERDR_FOCUS" ;;
          agent) herdr agent focus "$HERDR_FOCUS" ;;
          *) herdr tab focus "$HERDR_FOCUS" ;;
        esac
```

Set `HERDR_ICON_SET` to `color` (default), `mono-dark`, or `mono-light`. No
icon font is required.

<Image src={herdrStatusScreenshot} alt="Herdr demo agents grouped under Working, Waiting and Idle, with terminal output for the selected agent" width={800} />

Three views are available via Ctrl+Tab (`Workspaces`, `Status`, and `Agents`):

- `HERDR_VIEW: workspace` (`--tree`, default) shows the full workspace, tab,
  and pane tree.
- `HERDR_VIEW: status` (`--status`) groups agents across all workspaces under
  `Working`, `Waiting` (Herdr's `blocked`), `Idle`, `Done`, and `Unknown`,
  hiding empty groups. Group headings are non-selectable; search `waiting` or
  `blocked` to jump straight to agents needing input.
- `args: ["--agents"]` shows a flat list of recognized agents only.

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Herdr Agents"
      keyword: "hagents"
      command: "~/.config/raffi/scripts/herdr/herdr_filter.py"
      args: ["--agents"]
      icon: "utilities-terminal"
      action: 'herdr agent focus "$HERDR_FOCUS"'
```

To raise your terminal window before focusing a Herdr target, prepend your
compositor's focus command (replacing `kitty` with your terminal's class or app
id):

```sh
# Hyprland
hyprctl dispatch focuswindow class:kitty;
# Sway
swaymsg '[app_id="kitty"] focus';
# niri (requires jq)
id=$(niri msg -j windows | jq -r '.[] | select(.app_id == "kitty") | .id' | head -n1);
[ -z "$id" ] || niri msg action focus-window --id "$id";
```

With the preview pane open, Raffi refreshes the selected row every 2 seconds:
agent panes show status, directory, and recent terminal output; tabs list their
panes (or terminal output for single-pane tabs); workspaces list their tabs and
active tab. See the
[Herdr script README](https://github.com/chmouel/raffi/blob/main/scripts/herdr/README.md)
for details.
