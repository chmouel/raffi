Script filters allow external commands to provide dynamic results in the launcher using a subset of the Alfred Script Filter JSON format.

<Aside type="note">
Script filters are only available in **native mode**. They are not available when using Fuzzel mode.
</Aside>

## Overview

Script filters execute external commands when a keyword is typed, displaying dynamic results based on the command's JSON output. This enables integration with APIs, databases, custom scripts, and more.

<Image src={scriptFilterTzScreenshot} alt="Script filter timezone converter example" width={800} />

## Configuration

Configure script filters in your `raffi.yaml`:

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Timezones"
      keyword: "tz"
      command: "batz"
      args: ["-j"]
      icon: "clock"

    - name: "Bookmarks"
      keyword: "bm"
      command: "my-bookmark-script"
      args: ["-j"]
      action: "echo -n {value}|wl-copy"
      secondary_action: "xdg-open {value}"
```

### Configuration Fields

**`name`** `string` (required)

Display name shown during loading


**`keyword`** `string` (required)

Text that activates the script filter


**`command`** `string` (required)

Executable to run


**`args`** `array`

Arguments passed before the query


**`icon`** `string`

Fallback icon name for results without their own icon


**`action`** `string` (default: `copy`)

Action on Enter. Options:
  - `"copy"`: Copy to clipboard
  - `"insert"`: Type into focused app via wtype/ydotool
  - Command template with `{value}` placeholder (executed via `sh -c`)


**`secondary_action`** `string`

Action on Ctrl+Enter. Accepts same values as `action`. If omitted, Ctrl+Enter behaves same as Enter.


**`dynamic_preview`** `boolean` (default: `true`)

Ask the script for a preview of the selected item. See [Dynamic previews](#dynamic-previews). Set to `false` to only use the `preview` field from the item list.


## JSON Format

Script filters must output JSON matching this structure (subset of [Alfred's format](https://www.alfredapp.com/help/workflows/inputs/script-filter/json/)):

```json
{
  "items": [
    {
      "title": "New York",
      "subtitle": "EST (UTC-5) — 14:30",
      "arg": "America/New_York",
      "icon": { "path": "/usr/share/icons/clock.png" }
    },
    {
      "title": "London",
      "subtitle": "GMT (UTC+0) — 19:30",
      "arg": "Europe/London"
    }
  ]
}
```

### JSON Fields

**`title`** `string` (required)

Main text displayed for the item


**`subtitle`** `string`

Secondary text shown below the title


**`arg`** `string`

Value copied to clipboard (falls back to title if omitted)


**`indent`** `integer`

Raffi extension for tree-style results (Alfred ignores it): indentation
level of the item, `0` by default. Each level shifts the row further right
in the result list and adds subtle connector guides in the native UI, so a
script can return a hierarchy — for example the Herdr filter's workspace /
tab / pane tree:

```json
{
  "items": [
    { "title": "raffi [working]", "subtitle": "1 tab · 2 panes", "arg": "w1", "indent": 0 },
    { "title": "Feature [working]", "subtitle": "copilot, shell", "arg": "w1:t1", "indent": 1 },
    { "title": "copilot [working] - raffi", "arg": "w1:p1", "indent": 2 },
    { "title": "shell - raffi", "arg": "w1:p2", "indent": 2 }
  ]
}
```

Filtering stays the script's job: it receives the query as its last
argument and can return only the matching nodes plus their ancestors.

<Image src={herdrTreeScreenshot} alt="Herdr demo workspace tree with connected session and pane rows and the selected split session's details" width={800} />

<Image src={herdrStatusScreenshot} alt="Herdr demo agents grouped under Working, Waiting and Idle, with terminal output for the selected agent" width={800} />

Return parents before their children, with each subtree kept together.
The nearest preceding row with a smaller `indent` is the parent; skipped
levels do not create extra rows. A row without a parent keeps its offset
without drawing a branch to a missing ancestor. Offsets stop growing at ten
levels, but deeper rows keep their original relationships. Connections that
would overlap at that limit are omitted. Guides describe only displayed
rows and stop at source boundaries, including truncated main-view results.

**`valid`** `boolean`

Defaults to `true`. Set `false` for informational rows or tree headings.
They can be highlighted to read their preview, but Enter, Ctrl+Enter, and
click activation do not run an action or close Raffi. These rows are not
recorded as recent picks and do not count as selectable results for `--select-1`.

**`icon.path`** `string`

Absolute path to a PNG or SVG icon


**`preview`** `string` or `object`

Optional multiline preview text (supports ANSI escape codes) or local file/image path rendered in the right-hand preview pane. It can also be a [preview object](#preview-object), with `"dynamic": false` added to skip the dynamic preview call for this item


**`variables`** `object`

Optional Alfred string map. Each entry is exported as an environment variable to the preview call and to the `action` and `secondary_action` commands, so the script can pass structured data along without packing it into `arg`


**`quicklookurl`** `string`

Optional Alfred QuickLook URL or local file path (`file://`, `/path`, or `~/path`). Local files and images are previewed in the right-hand pane


**`text.largetype`** `string`

Optional Alfred large-type text shown in the right-hand preview pane when `preview` is omitted


**`text.copy`** `string`

Optional Alfred copy text metadata shown in the right-hand preview pane


## How It Works

<Steps>
1. **Type Keyword**

   User types the configured keyword followed by a space (e.g., `tz `). Until
   that space is typed, Raffi keeps searching launchers and offers a row
   describing the filter, which Enter or Tab activates.

2. **Execute Command**

   Script is executed with remaining input as final argument:
       ```bash
       batz -j "New York"
       ```

3. **Parse JSON**

   Raffi parses the JSON output from stdout

4. **Display Results**

   Items are displayed in the launcher

5. **Handle Selection**

   On Enter, the item's `arg` value (or `title`) is used with the configured action

</Steps>

A script filter listed in
[`general.main_view`](../../configuration/general-settings/#main-view) also runs
without its keyword: its first five items show in the main list each time
you pause typing, once the query reaches `min_query_length`.

## Dynamic Previews

When the preview pane is open (`Ctrl+P`), Raffi runs the script filter again
for the selected item and shows the preview object it prints. The command, args,
and query are the same as for the item list, with these environment variables
added:

| Variable | Value |
|----------|-------|
| `RAFFI_PREVIEW` | `1` |
| `RAFFI_VALUE` | the item's `arg`, or its title |
| `RAFFI_TITLE` | the item's title without ANSI codes |
| `RAFFI_QUERY` | the text typed after the keyword |
| `RAFFI_PREVIEW_WIDTH`, `RAFFI_PREVIEW_HEIGHT` | preview pane size in pixels |
| `RAFFI_THEME`, `RAFFI_THEME_MODE`, `RAFFI_THEME_FG`, ... | the current theme, see [Terminal Colours](../themes/#terminal-colours) |

The config `env` and the item's `variables` are exported too. The call is
debounced while you move through the list, killed after 3 seconds, and its
output is capped at 8 MiB.

A script supports this by checking `RAFFI_PREVIEW` before building its list:

```python
import json, os

if os.environ.get("RAFFI_PREVIEW") == "1":
    value = os.environ["RAFFI_VALUE"]
    print(json.dumps({"title": value, "text": f"Details for {value}"}))
    raise SystemExit
```

<Aside type="caution">
Previews run the script filter command again, so a command that changes
something each time it runs (sends a request with side effects, writes state)
must check `RAFFI_PREVIEW` first, or the filter needs `dynamic_preview: false`.
</Aside>

Scripts that ignore `RAFFI_PREVIEW` keep working. Raffi waits for the first
preview run of a script filter to answer before starting another. Any JSON
object without an `items` key is a preview object, so `{}` is an empty
preview. If the first run fails, times out, or prints something other than a
preview object (for example the usual `{"items": [...]}` or text that is not
JSON), Raffi stops asking that script filter for the rest of the session and
uses the item's `preview` field.

Once a script filter has printed a preview object, even one Raffi cannot read
(such as a field with the wrong type), errors are shown instead: a failed run
(non-zero exit or timeout) or an unreadable preview object keeps the last
preview on screen, adds a `Preview` row with the error, and is retried the
next time the item is selected.

### Preview Object

Every field is optional:

```json
{
  "title": "claude [working]",
  "subtitle": "project-a",
  "badge": "Herdr",
  "icon": "utilities-terminal",
  "text": "\u001b[32mANSI text\u001b[0m",
  "image": "/tmp/shot.png",
  "sections": [
    { "type": "text", "heading": "Output", "content": "..." },
    { "type": "image", "base64": "iVBORw0KGgo..." },
    { "type": "file", "path": "~/notes.md" }
  ],
  "metadata": [["Status", "working"], ["Directory", "/home/me/project-a"]],
  "refresh": 2
}
```

**`title`**, **`subtitle`**, **`badge`**: replace the header of the preview pane.

**`icon`**: icon theme name, image path, or emoji.

**`text`**: body text, ANSI colours supported (16, 256, and 24-bit).

**`image`**: a local image path, or `{"path": "..."}`, or `{"base64": "..."}`.
Base64 data may also be a `data:image/...;base64,` URL. Use
`RAFFI_PREVIEW_WIDTH` and `RAFFI_PREVIEW_HEIGHT` to size generated images.

**`sections`**: ordered body blocks. `text` takes `content` and an optional
`heading`, `image` takes `path` or `base64`, and `file` takes a `path` shown
with the same viewer as the file browser (text, images, directories). When
`sections` is set, `text` and `image` are ignored, and an empty list clears the
body. Without it the image comes first, then the text. A preview with no
`sections`, `text`, or `image` keeps the item's own preview body and only
changes the header and metadata.

**`metadata`**: `[label, value]` rows shown above Raffi's own Enter and
Ctrl+Enter rows.

**`refresh`**: seconds after which Raffi asks again while the item stays
selected, between 0.5 and 3600. Use it for live data such as logs or
progress. A `file` section is read again on every refresh.

The same object can be used as an item's static `preview` field (`refresh` has
no effect there). Add `"dynamic": false` to it to keep that item out of the
dynamic preview calls.

## ANSI Color Support

The `title` and `subtitle` fields support ANSI color codes for colored text:

```json
{
  "items": [
    {
      "title": "\u001b[32mSuccess\u001b[0m",
      "subtitle": "\u001b[90mCompleted at 14:30\u001b[0m"
    }
  ]
}
```

<Aside type="tip">
The [GitHub pull requests script](#github-pull-requests) uses colors to display the CI state of each pull request.
</Aside>

Titles, subtitles and preview text understand 16, 256 and 24-bit colours plus
bold, dim, italic and underline. The 16 basic colours come from the
[theme's palette](../themes/#terminal-colours). Other escape sequences, such as cursor
movement or terminal hyperlinks, are removed, and tabs are expanded to 8
columns, so output captured from tools like `bat` or `eza` displays cleanly.

### GitHub Pull Requests

<Image src={scriptFilterPrScreenshot} alt="GitHub PR browser" width={800} />

The [`scripts/github/pr.py`](https://github.com/chmouel/raffi/blob/main/scripts/github/pr.py) script in the repository lists open pull requests with their CI status, review decision, conflicts,
unresolved threads and size, using the [GitHub CLI](https://cli.github.com).

Install the script:

```bash
mkdir -p ~/.config/raffi/scripts/github
cp scripts/github/pr.py ~/.config/raffi/scripts/github/pr.py
chmod +x ~/.config/raffi/scripts/github/pr.py
```

Configure the filter:

```yaml raffi.yaml
script_filters:
  - name: "Pull Requests"
    keyword: "pr"
    command: "~/.config/raffi/scripts/github/pr.py"
    icon: "github"
    action: "xdg-open {value}"
    secondary_action: "copy"
```

Usage:

```text
pr
# Lists your open pull requests across all repositories
pr review
# Pull requests waiting for your review (also: assigned, involved)
pr owner/repo login
# Lists open pull requests of owner/repo matching "login"
# Enter: open the pull request in the browser
# Ctrl+Enter: copy its URL
```

Cross-repository modes group results under non-actionable repository-owner
headings (organizations or user accounts) when the filtered results span
multiple owners. Pull requests are indented beneath each heading; single-owner
results and fixed `owner/repo` queries stay flat.

Add `args: ["--repo", "owner/repo"]` to give a repository its own keyword, and
`ALIAS_<name>` variables in `env` for short repository names. Each row exports
`PR_URL`, `PR_REPO`, `PR_NUMBER` and `PR_BRANCH` to the actions.

Each pull request shows the avatar of its repository owner, or of its author
when every listed pull request comes from the same repository, cached under
`~/.cache/raffi/github-avatars/`. With the preview pane open, the selected pull
request shows its branches, each reviewer's verdict, merge state, unresolved
threads, checks, the issues it closes, its description with the markdown
rendered in colour, the latest comments from people and the changed files. It
refreshes every 20 seconds while a check is still running.

See the script's
[README](https://github.com/chmouel/raffi/blob/main/scripts/github/README.md)
for all options.

### Herdr Sessions

The [Herdr filter script](https://github.com/chmouel/raffi/tree/main/scripts/herdr)
browses a [Herdr](https://herdr.dev) session as an indented tree of workspaces,
tabs, and panes, using the `indent` field. Single-pane tabs, including
shells, appear once as the tab/session row; tabs with multiple panes show
their pane children. The query matches tab and pane details and keeps the
ancestors of each match. Single-pane tabs retain their terminal preview.
Select a workspace to focus it, a tab to focus it, or an agent pane to focus
the agent.

Install the script:

```bash
mkdir -p ~/.config/raffi/scripts/herdr
cp scripts/herdr/herdr_filter.py ~/.config/raffi/scripts/herdr/herdr_filter.py
cp -R scripts/herdr/icons ~/.config/raffi/scripts/herdr/
chmod +x ~/.config/raffi/scripts/herdr/herdr_filter.py
```

Copy the icon directory when upgrading too, including its license notices.
The default `color` icons distinguish workspaces, sessions, shells, and
agents. Preview headers use the same icons. Set `HERDR_ICON_SET` in the
filter's `env` to choose `color`, `mono-dark` (pale marks for dark themes),
or `mono-light` (dark marks for light themes). No icon font is required.

For an agent-only status tree, set `HERDR_VIEW: status` in the same `env`
block or add `args: ["--status"]`. Agents across workspaces appear under
Working, Waiting (Herdr's `blocked`), Idle, Done, and Unknown; empty groups
are hidden. Each agent appears once, including agents in split tabs, with
workspace context in its subtitle. Plain shells stay in the workspace view.
Group headings show matching counts and summary previews without an action.
Agent rows retain focus actions and terminal previews. Search `waiting`
or `blocked` to find agents needing attention. The workspace tree remains
the default (`HERDR_VIEW: workspace` or `--tree`), and `--agents` stays flat.

Configure the filter. Every item exports `HERDR_KIND` (`workspace`, `tab`,
`agent`, or `pane`) and `HERDR_FOCUS`, the ID to focus, so the action
dispatches on the kind:

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Herdr"
      keyword: "herdr"
      command: "~/.config/raffi/scripts/herdr/herdr_filter.py"
      icon: "utilities-terminal"
      env:
        HERDR_ICON_SET: color
      action: >-
        case "$HERDR_KIND" in
          workspace) herdr workspace focus "$HERDR_FOCUS" ;;
          tab) herdr tab focus "$HERDR_FOCUS" ;;
          agent) herdr agent focus "$HERDR_FOCUS" ;;
          *) herdr tab focus "$HERDR_FOCUS" ;;
        esac
```

To list only recognized agents instead of the whole tree, add
`args: ["--agents"]` and focus agents directly:

```yaml raffi.yaml
addons:
  script_filters:
    - name: "Herdr Agents"
      keyword: "hagents"
      command: "~/.config/raffi/scripts/herdr/herdr_filter.py"
      args: ["--agents"]
      icon: "utilities-terminal"
      action: 'herdr agent focus "$HERDR_FOCUS"'
```

To raise the terminal window before focusing, prepend the matching command
below to the action above. Change `kitty` to your terminal's class or app ID:

Hyprland:

```yaml
action: >-
  hyprctl dispatch focuswindow class:kitty;
  case "$HERDR_KIND" in
    workspace) herdr workspace focus "$HERDR_FOCUS" ;;
    tab) herdr tab focus "$HERDR_FOCUS" ;;
    agent) herdr agent focus "$HERDR_FOCUS" ;;
    *) herdr tab focus "$HERDR_FOCUS" ;;
  esac
```

Sway:

```yaml
action: >-
  swaymsg '[app_id="kitty"] focus';
  case "$HERDR_KIND" in
    workspace) herdr workspace focus "$HERDR_FOCUS" ;;
    tab) herdr tab focus "$HERDR_FOCUS" ;;
    agent) herdr agent focus "$HERDR_FOCUS" ;;
    *) herdr tab focus "$HERDR_FOCUS" ;;
  esac
```

niri (requires `jq`):

```yaml
action: >-
  id=$(niri msg -j windows | jq -r '.[] | select(.app_id == "kitty") | .id' | head -n1);
  [ -z "$id" ] || niri msg action focus-window --id "$id";
  case "$HERDR_KIND" in
    workspace) herdr workspace focus "$HERDR_FOCUS" ;;
    tab) herdr tab focus "$HERDR_FOCUS" ;;
    agent) herdr agent focus "$HERDR_FOCUS" ;;
    *) herdr tab focus "$HERDR_FOCUS" ;;
  esac
```

With the preview pane open, the selected row shows a live preview refreshed
every 2 seconds: agent panes show their status, directory, and recent
terminal output; tabs show their pane list (and the terminal of single-pane
tabs); workspaces show their tab list and active tab.

See the script's
[README](https://github.com/chmouel/raffi/blob/main/scripts/herdr/README.md) for
installation and usage.

### Web Search with Autocomplete

The [`scripts/search/search.py`](https://github.com/chmouel/raffi/blob/main/scripts/search/search.py) script in the repository provides live DuckDuckGo autocomplete suggestions while opening results in any configured search engine.

Install it first:

```bash
mkdir -p ~/.config/raffi/scripts/search
cp scripts/search/search.py ~/.config/raffi/scripts/search/search.py
chmod +x ~/.config/raffi/scripts/search/search.py
```

Then configure one entry per engine:

```yaml raffi.yaml
script_filters:
  - name: "Search DuckDuckGo"
    keyword: "ddg"
    command: "python3"
    args: ["~/.config/raffi/scripts/search/search.py", "duckduckgo"]
    icon: "web-browser"
    action: "xdg-open {value}"
    secondary_action: "copy"

  - name: "Search Google"
    keyword: "sg"
    command: "python3"
    args: ["~/.config/raffi/scripts/search/search.py", "google"]
    icon: "google"
    action: "xdg-open {value}"
    secondary_action: "copy"
```

Supported engines: `google`, `duckduckgo`, `bing`, `brave`.

Usage:

```text
ddg rust async
# First item: raw query "rust async" → opens DuckDuckGo search
# Remaining items: DDG autocomplete suggestions
# Enter: open in browser
# Ctrl+Enter: copy URL to clipboard
```

With the preview pane open, the selected suggestion shows the DuckDuckGo Instant Answer for it (summary, source link, and image) when there is one.

<Aside type="note">
Suggestions are fetched from the DuckDuckGo autocomplete API (no API key required). On timeout or network error the script falls back to showing the raw query only.
</Aside>

<Aside type="tip">
This is different from the `web_searches` addon, which opens a URL directly without autocomplete. Use `web_searches` for instant access to a URL, and this script filter when you want live suggestions.
</Aside>

## Creating a Script Filter

Here's a simple example script in Python:

```python my-filter.py
#!/usr/bin/env python3
import json
import sys

query = sys.argv[1] if len(sys.argv) > 1 else ""

items = [
    {
        "title": f"Result for: {query}",
        "subtitle": "This is a subtitle",
        "arg": f"https://example.com/search?q={query}",
        "icon": {"path": "/usr/share/icons/search.png"}
    }
]

print(json.dumps({"items": items}))
```

Make it executable and configure:

```bash
chmod +x my-filter.py
```

```yaml raffi.yaml
script_filters:
  - name: "My Filter"
    keyword: "mf"
    command: "./my-filter.py"
    action: "xdg-open {value}"
```

## Keyboard Shortcuts

- **Enter**: Execute primary action
- **Ctrl+Enter**: Execute secondary action (if configured)
- **Esc**: Cancel and return to normal mode
- **↑/↓**: Navigate through results

## Requirements

<Aside type="caution">
Your script must output valid JSON to stdout. Any errors should go to stderr.
</Aside>

<Aside type="note">
Clipboard actions require `wl-copy`, `xclip`, or `xsel`
</Aside>

<Aside type="note">
Insert/type actions require `wtype` or `ydotool`
</Aside>

## Tips

<Aside type="tip">
Test your script manually before adding to Raffi:
```bash
my-script -j "test query"
```
</Aside>

<Aside type="tip">
Use colors in output to highlight important information (ANSI codes are rendered)
</Aside>

<Aside type="tip">
Cache expensive operations in your script to improve performance
</Aside>

<Aside type="tip">
Set both `action` and `secondary_action` for maximum flexibility (e.g., copy vs. open)
</Aside>
