Type `sys ` (with the trailing space) to list session, display and power commands.
Words after the keyword filter the list, so `sys reb` leaves only Reboot.

<Aside type="note">
System commands are on by default.
</Aside>

| Entry       | Default command |
|-------------|-----------------|
| Lock        | `loginctl lock-session` |
| Display off | Hyprland's dpms dispatcher on Hyprland (through `hyprctl eval` with a Lua config, `hyprctl dispatch dpms off` otherwise), `swaymsg 'output * power off'` on sway, `niri msg action power-off-monitors` on niri; hidden elsewhere |
| Suspend     | `systemctl suspend` |
| Hibernate   | `systemctl hibernate` |
| Log out     | Hyprland's exit dispatcher on Hyprland, `niri msg action quit --skip-confirmation` on niri, `swaymsg exit` on sway, otherwise `loginctl terminate-session $XDG_SESSION_ID` |
| Reboot      | `systemctl reboot` |
| Shut down   | `systemctl poweroff` |

To open the list from a key binding, pass the keyword as the initial query:

```sh
raffi -i "sys "
```

<Aside type="caution">
The `sys ` keyword takes over any search starting with "sys ", so a launcher
search such as `sys monitor` opens the system commands instead. Set
`addons.system.trigger` to another keyword, or `addons.system.enabled: false`,
if you need those searches.
</Aside>

## Confirmation

Lock runs on the first Enter. Every other entry asks first: the row reads
"Press Enter again to reboot", and only a second Enter on the same entry runs
it. Moving the selection, editing the query, or pressing or releasing a
modifier cancels the request. Holding Enter down does not confirm.

If the program behind an entry is not installed, the row says so (for
example "hyprlock not found") and Enter does nothing. On Hyprland, Log out
uses `hyprctl eval` with a Lua config (Hyprland 0.55 or later) and
`hyprctl dispatch exit` otherwise. On niri it asks niri to quit without its
own confirmation dialog, and on sway it runs `swaymsg exit`. Elsewhere, the
default Log out needs
`XDG_SESSION_ID`; without it the row says so.

Raffi closes before running the command, unless
[`close_on_action`](#configuration) keeps it open. If the command fails, Raffi
reports the error as a notification (a Hyprland notification on Hyprland,
`notify-send` elsewhere).

Queries typed in this mode are saved in the search history when you run an
action.

## Configuration

**`addons.system.enabled`** `boolean` (default: `true`)

Enable or disable the system commands.

**`addons.system.trigger`** `string` (default: `sys`)

Keyword that opens the list. Type it followed by a space. Web searches with
the same keyword take precedence.

**`addons.system.commands`** `object`

Replaces built-in commands. Keys are `lock`, `display_off`, `suspend`, `hibernate`, `logout`, `reboot` and
`shutdown`. Each value is an argument list, run
directly without a shell. An empty list hides the entry.

**`addons.system.hide`** `list` (default: `[]`)

Entries to leave out, using the same names as `commands`.

**`addons.system.close_on_action`** `boolean` (default: `true`)

Close Raffi before running a command. Leave it unset to follow
`general.close_on_action`. Setting it to `false` keeps Raffi open after
Lock, Suspend and Hibernate; Display off, Log out, Reboot and Shut down always
close it.

```yaml
addons:
  system:
    trigger: "power"
    commands:
      lock: ["hyprlock"]
      logout: ["uwsm", "stop"]
    hide: [hibernate]
```
