Raffi can browse the clipboard history kept by [CopyQ](https://hluk.github.io/CopyQ/),
or record one itself with the [Raffi backend](#raffi-backend). Raffi gives you
a keyboard-driven list with search, previews, and copy or paste of any past
item.

<Image src={clipboardScreenshot} alt="Clipboard history with a demo release checklist selected and its multiline text in the preview pane" width={800} />

<Aside type="note">
The clipboard browser turns itself on
when its backend is running as Raffi starts (CopyQ, or `raffi --cache-daemon`
for the Raffi backend), unless you set `enabled` yourself.
</Aside>

## Setup

Install CopyQ and keep it running. Raffi talks to it through the `copyq`
command, so the binary must be on your `PATH`. Raffi never reads CopyQ's
files directly, and it does not record anything itself.

Raffi then enables the addon on its own. To keep it on even when CopyQ is not
running yet, or to turn it off, set `enabled`:

```yaml
addons:
  clipboard:
    enabled: true
```

Type `clip ` (with the trailing space) to open the history. Typing `cl` offers
the keyword as a suggestion. To open it straight from a key binding, pass the
keyword as the initial query:

```sh
raffi -i "clip "
```

## Browsing and searching

An empty query lists the whole history, newest first, in CopyQ's order. Words
after the keyword filter it. Every word must appear somewhere in the item's
text or file names, case-insensitively. Items that start with the exact phrase
come first, then items containing the phrase, then items containing all the
words in any order.

Raffi reads the history in batches of 400 items, so large histories show
results right away and the footer reads `scanning N/M` until the scan ends.
Search covers the full text of every item, not only what fits in the row.

Raffi browses the tab CopyQ uses for the clipboard (its `clipboard_tab`
setting, or the first tab). If the history changes during a scan, Raffi starts
the scan over. Press **Ctrl+R** to reload the list at any time.

Text entries shorter than three characters, such as a stray `#` or a single
letter, are hidden. Surrounding spaces and newlines don't count. Change the
limit with `min_chars`, or set it to `0` to list everything. Images and files
are always listed.

Row titles stay on one line. A line break inside a multi-line entry shows as a
return arrow (taken from your Nerd Font), so a pasted block of text is easy to
tell from a single line. Runs of spaces collapse to one.

## Copy times

The preview pane shows when an item was copied, in the summary line under
text and images and in the details of other items: "today at 14:32",
"yesterday at 09:10", the weekday for the past week ("Monday at 18:05"), and
the weekday and date for anything older ("Monday, March 2 at 10:00"). Rows
leave it out to stay compact.

CopyQ does not record copy times by default. Add the "Show Copy Time" command
from the [CopyQ command examples](https://copyq.readthedocs.io/en/latest/command-examples.html#show-copy-time)
or from [copyq-commands](https://github.com/hluk/copyq-commands/blob/master/commands/store-copy-time.ini)
(in CopyQ, press F6 and paste it). Raffi reads the time from either version.
Items copied before you add the command show no time.

## Source app icons

Each row can show the icon of the app you copied from. CopyQ does not record
the source app on Wayland, so add this command to CopyQ (press F6 in CopyQ and
paste it). It works on Hyprland and sway: whenever the clipboard changes, it
asks the compositor which window has focus and stores that app's ID with the
item.

```ini
[Command]
Name=Store Source App
Automatic=true
Icon=
Command="
    copyq:
    const mime = 'application/x-copyq-user-source-app';

    function hyprland() {
        const result = execute('hyprctl', 'activewindow', '-j');
        if (!result || result.exit_code !== 0) { return ''; }
        const window = JSON.parse(str(result.stdout) || '{}');
        return window.class || window.initialClass || '';
    }

    function sway() {
        const result = execute('swaymsg', '-t', 'get_tree');
        if (!result || result.exit_code !== 0) { return ''; }
        const stack = [JSON.parse(str(result.stdout))];
        while (stack.length) {
            const node = stack.pop();
            if (node.focused) {
                return node.app_id || (node.window_properties || {}).class || '';
            }
            stack.push(...(node.nodes || []), ...(node.floating_nodes || []));
        }
        return '';
    }

    let app = '';
    try {
        if (str(env('HYPRLAND_INSTANCE_SIGNATURE'))) { app = hyprland(); }
        else if (str(env('SWAYSOCK'))) { app = sway(); }
    } catch (e) {}
    if (app) { setData(mime, app); }"
```

Raffi looks the ID up in your icon theme, as given and then lowercased, and
leaves the icon out when the theme has none. The command records the window
that had focus, which is the app you copied from when you press Ctrl+C. A copy
made in the background, such as by `wl-copy`, a password manager or clipboard
sync, gets whatever app was in front at the time. Items copied before you add
the command show no icon.

## Images and URLs

Press **Ctrl+Tab** to go from all items to images only, then to URLs only,
then back to all items. **Ctrl+Shift+Tab** goes the other way, and the footer
shows the current view. [More on Ctrl+Tab](../../reference/keyboard-shortcuts/#switching-views-with-ctrltab). A URL is a text item that holds nothing but a link
with a scheme, such as `https://...`, `file:///...` or `mailto:...`.

Your choice holds while you type, and Raffi lists everything again the next
time you open the browser. Search words still apply to images, though most
images carry no text to match.

## Previews

Press **Ctrl+P** to toggle the preview pane. For text, it works like Alfred's
clipboard viewer: the bare text fills the pane, with no title, box or
metadata, and a muted `3 words; 33 chars · copied Monday at 10:00` line
centred underneath (the copy time appears when CopyQ stored one). For
everything else it shows:

- text, cut to the first 8 KiB or 100 lines (a cut item reports its full
  character count only)
- images, scaled to fit, with a muted `1920 × 1080 px · copied ...` line
  centred underneath
- file lists, with missing files marked
- the formats the item holds and their sizes

Rich text (HTML) items preview as plain text. Raffi never renders HTML or loads
remote content. Images larger than 32 MiB or 40 megapixels are not previewed,
though you can still copy them.

Previews stay in memory while the window is open and are never written to
disk.

## Actions

| Key        | Default action | Description                                   |
|------------|----------------|-----------------------------------------------|
| Enter      | `copy`         | Put the item back on the clipboard            |
| Ctrl+Enter | `hypr_paste`   | Copy, then paste into the window you came from |
| Ctrl+D     |                | Delete the item from the history (CopyQ or `clipboard.db`, with all its formats) |

Change them with `action` and `secondary_action`. Both accept `copy` and
`hypr_paste`.

Copying goes through CopyQ, which publishes every format the item holds, so
HTML keeps its formatting and images and file lists paste as such. Raffi checks
that the clipboard holds the item before closing. If the item disappeared from
the history since the list was loaded, Raffi shows an error and leaves the
clipboard alone. CopyQ moves a copied item to the top of its history.

`hypr_paste` needs Hyprland, as described in
[Text Snippets](../text-snippets/#default-actions). Raffi remembers the
window that had focus when it opened, copies the item, closes, and sends Ctrl+V
(Ctrl+Shift+V in terminals) once that window has focus again. If that window
closed, or you are not on Hyprland, Raffi shows an error and does not fall back
to copying.

## Raffi backend

With `backend: raffi`, Raffi records the clipboard itself and CopyQ is not
needed. Listing and previews read a local database, so the history opens
faster than through CopyQ, and copy times, source app icons and password
skipping work without extra commands. CopyQ stays the default.

The recorder runs inside the Raffi server
([`raffi --cache-daemon`](../../reference/cli-options/#cache-management)),
so start it and keep it running:

```bash
raffi --cache-daemon
```

```yaml
addons:
  clipboard:
    backend: raffi
    max_items: 1000       # entries kept
    max_size_mb: 500      # total size before the oldest entries go
    max_image_size_mb: 50 # larger images are not recorded
```

The server watches the clipboard through the compositor's data-control
protocol (`ext-data-control-v1`, or `wlr-data-control-unstable-v1` on older
compositors), which Hyprland, Sway, niri and most wlroots compositors offer.
For every copy it keeps:

- the text, as plain text, with `text/html` and file lists when the source
  offers them;
- one picture, in the best raster format offered (PNG, then JPEG, WebP, GIF,
  BMP), plus SVG when offered. Browsers offer one picture in many encodings,
  so only the best one is stored;
- the copy time, and the app that had focus (Hyprland, Sway and niri).

Copying the same content again moves it to the top. Copies marked
`x-kde-passwordManagerHint`, as KeePassXC and other password managers do,
are never recorded unless you [opt in to temporary password entries](#password-managers).
The primary selection is ignored, and Raffi does not
import an existing CopyQ history.

When you copy an entry from the list, the server puts it on the clipboard
with every stored format and keeps serving it, so it can still be pasted
after Raffi closes. If another app later closes, its last copy stays
available too, as with any clipboard manager.

The history lives in `~/.local/share/raffi/clipboard.db` (or under
`$XDG_DATA_HOME`), readable only by you. Restart the server after changing
the backend or the limits. The shipped `misc/systemd/raffi-cache.service`
grants write access to `~/.local/share/raffi` only, so update its
`ExecStartPre` and `ReadWritePaths` lines if you move `$XDG_DATA_HOME`.

## Temporary entries

Some copies should not stay in the history: a one-time code, a password, a
token. The `raffi` backend can keep them for a while and then forget them:

```yaml
addons:
  clipboard:
    backend: raffi
    temporary_patterns:
      - '(?i)^verification code:'
      - '(?i)\bOTP\b'
      - '^sk-[A-Za-z0-9]{20,}$'
    temporary_timeout: 60          # seconds, default 60
    temporary_password_manager: true
```

An entry matching any of `temporary_patterns` is recorded as usual — listed,
searchable, previewable, copyable — and then leaves the history once
`temporary_timeout` seconds have passed since it was copied. The browser drops
such a row within a second of its deadline, and the server deletes the entry
and the formats stored for it from the database.

`temporary_patterns` take Rust regular expressions, in the same syntax as
`exclude_patterns`. They are matched against the entry's complete searchable
text: its plain text, or the text Raffi extracts from `text/html` when the copy
carries no plain text, plus the file names of a copied file list. The whole
text is searched, not just the visible excerpt, so a match far down a long
entry still counts. Matching is case-sensitive unless a flag such as `(?i)` is
given. `exclude_patterns` always wins: an excluded copy is never recorded,
temporary or not.

The deadline is measured from the moment of the copy. Copying the same content
again from another app resets it, and selecting the entry in the browser does
not extend it. The deadline is written with the entry, so changing
`temporary_timeout` later leaves existing entries alone.

Expiry only touches Raffi's history: the entry and the formats stored for it
are deleted, and the system clipboard is left alone. An entry you re-published
from the history stays on the clipboard after the entry itself is gone, and a
copy another app made meanwhile is never disturbed.

Deleted and expired entries are overwritten in `clipboard.db` and its
write-ahead log rather than left in free space, so their text cannot be
recovered from the file afterwards. The file itself does not shrink: SQLite
reuses the freed space for new copies, and it stays bounded by the history
limits, so no `VACUUM` is needed.

### Password managers

Password managers mark the secrets they copy with the
`x-kde-passwordManagerHint` MIME type. KeePassXC does, and so do the helpers of
rbw, Bitwarden and most other tools. The `raffi` backend detects that marker on
the clipboard itself: it never reads or unlocks your vault, and no
password-manager tool is needed. Copy helpers such as `rbw` are optional.

Marked copies are skipped by default. With `temporary_password_manager: true`
they are recorded as temporary entries instead and kept for
`temporary_timeout`. They are never kept permanently: no `temporary_patterns`
match makes them permanent, and `exclude_patterns` still wins over the opt-in.

A marked entry is never put back on the clipboard once the source app clears
it. When you select one, the server re-advertises the marker together with the
stored formats, so anything watching the clipboard still treats it as a
secret.

The CopyQ backend is unaffected by all three settings: CopyQ keeps its own
history, and Raffi only hides the entries `exclude_patterns` matches in the
browser.

Restart `raffi --cache-daemon` after changing any of them, since the recorder
reads them at startup. `raffi --check-config` reports an invalid regular
expression, and a `temporary_timeout` of zero or too large to be a deadline,
with the key and line of the setting.

## Privacy

Clipboard queries are saved in Raffi's search history and in the last-query
cache, so Alt+P and `--last-query` can bring them back. Debug logs still show
`clip <redacted>` in place of the query. Previews are discarded when the
window closes.

## Configuration

**`addons.clipboard.enabled`** `boolean` (default: unset)

Turns the clipboard browser on or off. When unset, it is on if the backend
is running as Raffi starts: CopyQ, or `raffi --cache-daemon` for `raffi`.

**`addons.clipboard.trigger`** `string` (default: `clip`)

Keyword that opens the history. Type it followed by a space.

**`addons.clipboard.min_chars`** `integer` (default: `3`)

Hide text entries shorter than this many characters, not counting
surrounding spaces and newlines. `0` lists everything. Images and files are
always listed.

**`addons.clipboard.exclude_patterns`** `string[]` (default: `[]`)

Rust regular expressions. An entry whose text matches any of them is never
recorded by the `raffi` backend and is hidden from the browser for both
backends. The whole text is searched, not just the visible excerpt, so a match
far down a long entry still excludes it. Matching is case-sensitive unless a
flag such as `(?i)` is given. Invalid expressions stop raffi at startup with
the key and index of the bad entry, and `raffi --check-config` reports them
with the line of the pattern.

Existing entries are hidden, not deleted. CopyQ keeps recording everything
itself; raffi only controls what its browser shows. A CopyQ entry whose
complete text cannot be checked, such as one over 16 MiB, is hidden while
patterns are set, and the `raffi` backend skips a copy when one of its text
formats cannot be read. After changing these patterns, restart
`raffi --cache-daemon` so the recorder picks them up.

**`addons.clipboard.temporary_patterns`** `string[]` (default: `[]`)

`raffi` backend: Rust regular expressions. A copy whose complete searchable
text matches any of them is recorded as a temporary entry, kept for
`temporary_timeout` seconds. `exclude_patterns` wins over these, and CopyQ is
unaffected. See [Temporary entries](#temporary-entries).

**`addons.clipboard.temporary_timeout`** `integer` (default: `60`)

`raffi` backend: seconds a temporary entry stays in the history, counted from
the copy. Copying the same content again resets it, selecting the entry does
not. Must be greater than zero.

**`addons.clipboard.temporary_password_manager`** `boolean` (default: `false`)

`raffi` backend: record copies carrying `x-kde-passwordManagerHint` as
temporary entries instead of skipping them. They are never kept permanently,
and `exclude_patterns` still wins.

**`addons.clipboard.backend`** `copyq | raffi` (default: `copyq`)

Clipboard manager to read from: CopyQ, or the history the Raffi server
records (see [Raffi backend](#raffi-backend)).

**`addons.clipboard.max_items`** `integer` (default: `1000`)

`raffi` backend: entries kept. The oldest ones are dropped beyond it.

**`addons.clipboard.max_size_mb`** `integer` (default: `500`)

`raffi` backend: total size of the history in MB before the oldest entries
are dropped. The newest entry is always kept.

**`addons.clipboard.max_image_size_mb`** `integer` (default: `50`)

`raffi` backend: images larger than this many MB are not recorded.

**`addons.clipboard.action`** `copy | hypr_paste` (default: `copy`)

What Enter does: `copy` puts the item back on the clipboard with all its
formats, and `hypr_paste` also pastes it into the window you came from on
Hyprland.

**`addons.clipboard.secondary_action`** `copy | hypr_paste` (default: `hypr_paste`)

What Ctrl+Enter does. Accepts the same values as `action`. Outside Hyprland
a `hypr_paste` action shows an error and does not copy.

**`addons.clipboard.close_on_action`** `boolean` (default: `true`)

Close Raffi after copying an item. Leave it unset to follow
`general.close_on_action`. `hypr_paste` always closes Raffi so it can paste.

```yaml
addons:
  clipboard:
    enabled: true
    trigger: clip
    min_chars: 3
    exclude_patterns:
      - '^secret:'
      - '(?i)password\s*='
    temporary_patterns:
      - '(?i)^verification code:'
      - '(?i)\bOTP\b'
    temporary_timeout: 60
    temporary_password_manager: false
    backend: copyq
    action: copy
    secondary_action: hypr_paste
```

## Troubleshooting

"CopyQ is not running" means the `copyq` command could not reach the CopyQ
server. Start CopyQ, then press **Ctrl+R**.

"CopyQ is not installed" means Raffi could not find the `copyq` command.

"Raffi clipboard service is not running" means the `raffi` backend is set
but no `raffi --cache-daemon` is running. Start it, then press **Ctrl+R**. If
the server log says the compositor does not support data-control, your
compositor cannot share the clipboard with a clipboard manager.

"Clipboard history kept changing" appears when items keep arriving during a
scan. Press **Ctrl+R** to try again.
