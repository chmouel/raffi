---
title: CLI Options
description: Command-line flags and options for Raffi
---

Raffi supports several command-line flags to control its behavior. All flags are optional and override settings from the configuration file.

## Global Flags

**`--help`** `boolean` (default: `false`)

Print help message and exit.


**`--version`** `boolean` (default: `false`)

Print version information and exit.


## Configuration

**`-c, --configfile`** `string` (default: `~/.config/raffi/raffi.yaml`)

Path to the YAML configuration file. Custom entries are read from `launchers.yaml` in the same directory when this file has no `launchers:` section.

  Supports tilde expansion (`~/`) and environment variable expansion (`${VAR}`).

  ```bash
  raffi -c ~/custom/config.yaml
  raffi --configfile ~/custom/config.yaml
  ```


**`-o, --option`** `KEY=VALUE` (repeatable)

Override any YAML configuration setting from the command line.

  Keys use dot-separated paths matching `raffi.yaml` (such as `general.theme=nord`, `addons.emoji.close_on_action=false`, or `launchers.firefox.close_on_action=false`). Sequence entries under `addons.script_filters`, `addons.web_searches`, and `addons.text_snippets` can be addressed by numeric index, `name`, or `keyword`. Values are parsed as YAML booleans, numbers, lists, or strings, and validated against the configuration schema.

  ```bash
  raffi -o general.close_on_action=false
  raffi -o addons.emoji.close_on_action=false -o general.theme=nord
  raffi -o 'addons.script_filters.Timezones.close_on_action=false'
  ```


**`--vim-mode`** `boolean` (default: `false`)

Start with modal vim keybindings in normal mode. Equivalent to `general.vim_mode: true`; the flag wins when both are set. `Ctrl+Alt+V` toggles vim mode at runtime.

  ```bash
  raffi --vim-mode
  ```


**`--keep-open`** `boolean` (default: `false`)

Keep the Raffi window open after executing an action (shorthand for `-o general.close_on_action=false`). Individual addons or entries can still override this via `-o addons.<name>.close_on_action=true`.

  ```bash
  raffi --keep-open
  ```


**`--check-config`** `boolean` (default: `false`)

Validate the configuration file and `launchers.yaml` next to it against the JSON Schema and exit without launching anything.

  Every problem is printed with the file name, line number and path of the offending key, for example `launchers.yaml:12: /firefox: Additional properties are not allowed ('binnary' was unexpected)`. The exit code is non-zero when problems are found. Old v0 (flat) configs are checked as if migrated, but the file is left untouched and line numbers refer to the original file.

  When nothing is wrong, Raffi also prints advisory warnings for the launcher entries, prefixed with `warning: `, for example `warning: launchers.yaml:5: /copyq/binary: 'copyq' is already driven by the builtin clipboard addon (keyword 'clip')`. They flag a `binary` or `ifexist` that is not installed on this machine, an entry an enabled builtin addon already covers, a `keyword` that collides with an addon or script filter keyword, a launcher keyword used twice, a launcher that asks to raise but has no window class to match, an installed app also listed by `addons.apps` (suggesting a `desktop` ID), a `desktop` ID with no matching application row on this machine, and disabled entries. Warnings that need the native UI, that is the addon ones and the `raise` one, only apply when it runs, so a `ui_type: fuzzel` configuration does not get them. These warnings never change the exit code, so `--check-config` stays usable in a pre-commit hook.

  Requires the `config-validation` Cargo feature, which is enabled by default. Builds made with `--no-default-features` report that validation is unavailable.

  ```bash
  raffi --check-config
  raffi --check-config -c ~/custom/config.yaml
  ```


**`--generate-schemas`** `boolean` (default: `false`)

Write or refresh both JSON Schema files next to the selected config file and
exit. Use `--configfile` to choose the config directory.

  ```bash
  raffi --generate-schemas --configfile /path/to/raffi.yaml
  ```


**`--install-browser-host`** `boolean` (default: `false`)

Register Raffi as the native messaging host of the Vicinae browser extension, for the [browser tabs](../../features/browser-tabs/) list, and exit.

  Writes a `com.vicinae.vicinae.json` manifest pointing to the running `raffi` binary for every Chromium or Firefox based browser with a configuration directory, and prints each file. A manifest Raffi did not install, such as one that starts Vicinae, is left alone unless `--force` is given.

  ```bash
  raffi --install-browser-host
  raffi --install-browser-host --force
  ```


**`--uninstall-browser-host`** `boolean` (default: `false`)

Remove the browser host manifests that start Raffi and exit. Manifests of other programs are kept.

  ```bash
  raffi --uninstall-browser-host
  ```


**`--force`** `boolean` (default: `false`)

With `--install-browser-host`, replace manifests Raffi did not install, such as the ones that start Vicinae.


## UI Options

**`-u, --ui-type`** `string`

By default Raffi opens its own window. Pass `fuzzel` to show your entries in
[Fuzzel](../../integration/fuzzel/) instead, a legacy option with fewer features.

  ```bash
  raffi -u fuzzel
  ```

**`--app-name`** `string` (default: `com.chmouel.raffi`)

Set the application ID reported for Raffi's window on Linux. This is useful for targeting the window with compositor or window-manager rules.

  ```bash
  raffi --app-name org.example.raffi
  ```


**`-I, --no-icons`** `boolean` (default: `false`)

Disable icon loading for faster startup.

  When enabled, no icons are shown. This can significantly speed up startup time, especially on first launch.

  ```bash
  raffi -I
  ```


**`-i, --initial-query`** `string`

Pre-fill the search field with an initial query.

  Useful for launching Raffi with a specific search term already entered.

  Addon keywords need their trailing space here too, so use `-i "sn "` to open a
  snippet source directly.

  Opening help temporarily clears the initial query so all help
  entries are visible. Closing help restores it.

  ```bash
  raffi -i firefox
  ```

**`--last-query`** `boolean` (default: `false`)

Print the last query typed in Raffi's search box and exit. Raffi's own window
records the raw text each time the query changes, so addon modes such as
`clip ` and script filters are included, and a script gets the exact keyword
and trailing space back. Nothing is printed when no query has been recorded
yet. Fuzzel does its own search and cannot record the typed query.

  ```bash
  raffi --last-query
  raffi -i "$(raffi --last-query)"
  ```

**`-1, --select-1`** `boolean` (default: `false`)

With a non-empty `--initial-query`, automatically activate the only selectable
result after its results finish loading. The option applies only to the
initial query; typing or refining the query later does not trigger automatic
activation.

  ```bash
  raffi -1 -i firefox
  raffi --select-1 --initial-query firefox
  ```

**`-t, --theme`** `string` (default: `dark`)

Select the color theme.

  Valid values:

- `dark` - Sleek Obsidian dark theme (default)
- `light` - Rose Pine Dawn light theme
- `catppuccin` / `catppuccin-mocha` - Catppuccin Mocha dark theme
- `catppuccin-latte` - Catppuccin Latte light theme
- `tokyo-night` / `tokyonight` - Tokyo Night dark theme
- `nord` - Nord dark theme
- `gruvbox` - Gruvbox dark theme
- `dracula` - Dracula dark theme
- `rose-pine` / `rosepine` - Rosé Pine dark theme
- `kanagawa` - Kanagawa Wave dark theme

  ```bash
  raffi -t tokyo-night
  ```

**`--opacity`** `number` (default: `0.95`)

Opacity of the window backgrounds, from `0.0` (see-through) to `1.0` (solid). Text and icons stay opaque. Overrides `general.opacity`. Below `1`, the default `renderer: auto` draws on the GPU, which transparency needs. See [Transparency and Blur](../../features/themes/#transparency-and-blur).

  ```bash
  raffi --opacity 0.7
  ```

## Execution Options

**`-p, --print-only`** `boolean` (default: `false`)

Print the command to stdout instead of executing it.

  Useful for debugging or integrating with window managers that execute commands separately.

  ```bash
  raffi -p
  # Output: env -- firefox --marionette
  ```

  The output is a **shell-ready command line**: arguments that need it are single-quoted, so the
  result is meant to be evaluated by a shell (`sh -c "$cmd"`) rather than word-split. Script entries
  print as `<interpreter> -c '<script>' [<interpreter> <args>...]`, which means a multi-line script
  produces multi-line output.

  Commands given by name are printed with an `env` prefix. That makes the receiving shell run the
  program from your `PATH`, the same one Raffi would launch itself, instead of a shell builtin,
  alias or function that happens to share the name. Entries configured with a full path are printed
  as-is.

  Example with Sway:

  ```bash
  cmd=$(raffi -p) && [ -n "$cmd" ] && swaymsg exec -- "$cmd"
  ```

  Do not pipe the output through `xargs`: `xargs` strips quotes and splits on whitespace, which
  mangles arguments containing spaces and breaks `script` entries. Always quote `"$cmd"`.


**`-P, --default-script-shell`** `string` (default: `bash`)

Set the default shell interpreter for script entries.

  Used when a configuration entry has a `script` field but no explicit `binary` field. Common values include `bash`, `zsh`, `sh`, `python3`, etc.

  ```bash
  raffi --default-script-shell zsh
  ```


## Cache Management

**`-r, --refresh-cache`** `boolean` (default: `false`)

Refresh every local cache.

  Raffi caches icon locations from system directories to speed up subsequent launches. Use this flag to force regeneration of the cache, for example after installing new icon themes. It also removes the private script-filter and browser-history snapshots, the Slack cache and the startup file list, and tells a running server to drop its state.

  ```bash
  raffi -r
  ```

  Caches live under `$XDG_CACHE_HOME/raffi/` (defaults to `~/.cache/raffi/`).


**`--server`** `boolean` (default: `false`)

Run the optional background server in the foreground. It warms the
script filters, Slack views and browser history you opted into, records the
clipboard for the [`raffi` clipboard backend](../../features/clipboard-history/#raffi-backend)
(under the default `auto` backend, only when CopyQ is not running as it starts),
and serves requests over `$XDG_RUNTIME_DIR/raffi/cache.sock`. Raffi never starts it
behind your back: run it from a terminal or a user service such as
`misc/systemd/raffi-server.service`.

  ```bash
  raffi --server
  ```

  `--cache-daemon` is accepted as an alias, so service units written before
the rename keep working.

  Without the server, Raffi still reads and writes the same private
  snapshots directly, so cached rows still show immediately; only the
  periodic warming while Raffi is closed is lost.

  The server also keeps Raffi's own startup files in memory. Each time the
  window opens, Raffi notes the files it needed to start (the binary, the
  graphics libraries, fonts, config and caches) in
  `~/.cache/raffi/hot-files.json`. Every few minutes the server reads them
  back, so the kernel does not evict them, and a launch after a long idle
  stays as fast as a warm one. When the files are already cached, a pass
  costs a few tens of milliseconds.

  When Raffi opens and finds the server running, the footer shows
  `server`. On a Slack view, browser history or a Script Filter with
  `cache_seconds`, it shows `F5 server refresh` instead: F5 asks the
  server to fetch that source again, waits for it, and reloads the list
  from the new snapshot. Ctrl+Shift+F5 does the same for every source the
  server caches, from any view, and has no footer hint. It runs script-filter
  lists even when a background refresh already has them, as F5 does. A
  successfully refreshed script filter on screen still reloads if another
  source fails.

  The footer warns `server config differs, restart it` when the server
  was started with a different addons configuration, and
  `server outdated, restart it` when the server cannot safely refresh cached
  lists. Both shortcuts require a restart in the second case. If the server
  stops while Raffi is open, F5 shows `server not reachable`.

  The server prints a line to its output each time F5 or Ctrl+Shift+F5
  asks for a refresh, then another with how long it took or why it failed:

  ```text
  raffi: refreshing slack:unread
  raffi: refreshed slack:unread in 0.7s
  ```


## Clipboard

`raffi clipboard` manages the [clipboard history](../../features/clipboard-history/)
without opening Raffi. It uses `addons.clipboard.backend` and the configured
exclusion patterns.

```sh
raffi clipboard list git -n 10
raffi clipboard list -k image --json
raffi clipboard show 1 > out.png
raffi clipboard copy 1
raffi clipboard set "hello"
raffi clipboard delete 3fa9c1d2e0
raffi clipboard clear -y
raffi clipboard status --json
```

`REF` is an ID or a unique ID prefix of at least six characters. `show` and
`copy` also accept a position in the default list. Positions can change as
new entries arrive, so use IDs in scripts. `show`, `copy` and `delete` accept
`-` to read references from standard input, one per line.

**`list [QUERY...]`**

List entries newest first. All query words must match, as in the browser.

- `-k, --kind KIND`: filter by `text`, `html`, `image`, `files`, `url` or `other`.
- `-n, --limit N` and `--offset N`: select a page of results.
- `--since WHEN`: filter by duration (`30s`, `15m`, `2h`, `3d`), RFC 3339
  timestamp or local date (`YYYY-MM-DD`). Entries without copy times are omitted.
- `--all`: include text shorter than `min_chars`.
- `--json`: print one JSON object per entry.

On a terminal, `list` prints a table. Redirected output is tab-separated:
ID, kind, copy time and preview. JSON includes those fields, the position,
formats, search tier, source, expiry, image dimensions and OCR status when
available. Fields that do not apply are `null`.

**`show REF`**

Write the entry's text, file paths or image to standard output. Redirect image
output to a file. `--mime TYPE` exports a specific format; `--formats` lists
available formats and sizes; `--json` prints metadata instead. `--mime` and
image export require the Raffi backend.

`--max-bytes N` limits the output. For JSON it limits text and OCR text;
`truncated` and `ocr_truncated` indicate whether either was shortened. Image
metadata includes OCR status, text, language and any error.

**`copy REF`**

Copy an entry with its formats. The Raffi backend needs `raffi --server`
running.

**`set [--mime TYPE] [--source APP] [--temporary] [--expire DURATION] [--secret] [--json] [TEXT...]`**

Put text or input on the clipboard and in the history. With no text arguments,
`set` reads standard input, unless it is a terminal. `--mime` sets the content type; the default is
`text/plain`. `--source` sets an app name or installed desktop entry ID.

`--temporary` keeps the entry for `temporary_timeout`. `--expire` accepts a
duration such as `30s` or `2h`, and also clears the clipboard at the deadline
if it still contains the entry. `--secret` marks the content for password-aware
clipboard managers. Exclusion patterns still apply. These options and `--source`
require the Raffi backend; CopyQ does not return the recorded ID.

`--json` reports the ID, whether the entry was recorded, and its expiry. The
Raffi backend needs the server running for `set`.

**`delete REF...`**

Delete entries by ID. References are resolved before any entry is removed.

**`clear [-k KIND] [-y|--yes]`**

Delete all entries, including those hidden by exclusion patterns. Use `-k` to
clear one kind and `-y` to skip confirmation. Requires the Raffi backend.

**`status [--json]`**

Show the backend, recorder status, history location, size and limits. Works
while the recorder is stopped.

The commands exit with 0 on success, 1 on an error and 2 for usage errors.
With `--json`, errors are JSON objects on standard error with `error`
and `code` fields. Codes include `not_found`, `ambiguous_ref`, `invalid_ref`,
`index_not_allowed`, `no_backend`, `recorder_not_running`, `server_outdated`,
`unsupported`, `too_large`, `no_history`, `io`, `invalid_argument` and `other`.

## Examples

### Basic Usage

Launch with default settings:

```bash
raffi
```

### Custom Configuration

Use a custom config file:

```bash
raffi --configfile ~/.config/work/raffi.yaml
```

### Light Theme

Launch with the light theme and no icons:

```bash
raffi -t light -I
```

### Print-Only Mode

Print the selected command without executing:

```bash
raffi -p
```

### Pre-filled Search

Launch with an initial search query:

```bash
raffi -i "screenshot"
```

### Refresh Icons and Use Custom Shell

Refresh icon cache and use zsh for scripts:

```bash
raffi -r --default-script-shell zsh
```

## Precedence

Command-line flags always take precedence over settings in the configuration file's `general` section. This allows you to override persistent defaults on a per-launch basis.
