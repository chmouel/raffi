## Configuration Files

Raffi reads two files from `$HOME/.config/raffi/`:

```
$HOME/.config/raffi/raffi.yaml       # general settings and addons
$HOME/.config/raffi/launchers.yaml   # launcher entries
```

Keeping launchers in `launchers.yaml` is the recommended layout: the file you edit most stays short and free of settings, and `raffi.yaml` only holds what you rarely touch. Both files are optional. Raffi reads `launchers.yaml` when `raffi.yaml` is missing or has no `launchers:` section of its own; if `raffi.yaml` does define launchers, those win and `launchers.yaml` is ignored with a warning.

You can override the location of `raffi.yaml` with the `-c` or `--configfile` flag. Raffi then looks for `launchers.yaml` in the same directory:

```bash
raffi --configfile /path/to/custom/raffi.yaml
```

Raffi writes `raffi-schema.json` and `launchers-schema.json` next to your config so editors can validate both files as you type, and warns on stderr about unknown or invalid keys when it starts. Run `raffi --check-config` to validate them on demand. See [Validation](../../reference/yaml-schema/#validation) for details.

## Basic Structure

`launchers.yaml` is a mapping of entry names to [entries](../entries/). `raffi.yaml` has two main sections:

1. **General settings** - UI preferences, theme, fonts, window dimensions
2. **Addons** - Optional features like script filters, web searches, text snippets

### Minimal Example

```yaml title="launchers.yaml"
firefox:
  binary: firefox
  args: [--marionette]
  icon: firefox
  description: Firefox browser with marionette enabled
```

### Complete Structure

```yaml title="raffi.yaml"
version: 1

# General settings (optional)
general:
  theme: dark
  font_size: 20
  window_width: 800
  window_height: 600

# Addons (optional)
addons:
  script_filters:
    - name: "Timezones"
      keyword: "tz"
      command: "batz"
      args: ["-j"]

  web_searches:
    - name: "Google"
      keyword: "g"
      url: "https://google.com/search?q={query}"
```

```yaml title="launchers.yaml"
firefox:
  binary: firefox
  description: "Firefox"
  icon: firefox
  args: ["--marionette"]

terminal:
  binary: kitty
  description: "Terminal"
  icon: terminal
```

### Launchers Inside raffi.yaml

A single file still works. Put the entries under a `launchers:` key in `raffi.yaml`, indented one level. The snippets in these docs are written for `launchers.yaml`; to use one in `raffi.yaml`, nest it under `launchers:`:

```yaml title="raffi.yaml"
version: 1

launchers:
  firefox:
    binary: firefox
    icon: firefox
```

## Path Expansion

Most configuration fields support path expansion:

- `~/` expands to your home directory
- `${VAR}` expands to environment variable values
- Unset variables expand to empty strings

```yaml title="launchers.yaml"
myapp:
  binary: ${HOME}/bin/myapp
  args: ["${XDG_DATA_HOME}/files", "~/Documents"]
  icon: ~/icons/myapp.png
  ifexist: ~/bin/myapp
```

<Aside type="note">
Path expansion is **not** applied to script content (`script` field). Only use it for paths, binaries, icons, and arguments.
</Aside>
