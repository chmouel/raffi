Raffi runs without any config. When you want to change how it looks, what the
main list shows or which addons are on, you write it in a YAML file.

## Configuration Files

Raffi reads two files from `$HOME/.config/raffi/`, and both are optional:

```
$HOME/.config/raffi/raffi.yaml       # settings and addons
$HOME/.config/raffi/launchers.yaml   # your own entries
```

`raffi.yaml` holds almost everything: the theme, fonts, what the main list
shows, which addons are on and their keywords, web searches, snippets and
script filters. `launchers.yaml` only holds commands and scripts you add
yourself, and many people never need it.

You can override the location of `raffi.yaml` with the `-c` or `--configfile` flag. Raffi then looks for `launchers.yaml` in the same directory:

```bash
raffi --configfile /path/to/custom/raffi.yaml
```

Raffi writes `raffi-schema.json` and `launchers-schema.json` next to your config so editors can validate both files as you type, and warns on stderr about unknown or invalid keys when it starts. Run `raffi --check-config` to validate them on demand. See [Validation](../../reference/yaml-schema/#validation) for details.

<Aside type="note">
With no config file at all, Raffi mixes windows, system commands and other
addons into the main list. Once a config file exists, the main list shows
only your apps and entries until you set
[`main_view`](../general-settings/#main-view).
</Aside>

## raffi.yaml

`raffi.yaml` has two main sections:

1. `general`: theme, fonts, window size, what the main list shows
2. `addons`: turn addons on or off, change their keywords, and add web searches, snippets and script filters

### Minimal Example

```yaml title="raffi.yaml"
general:
  theme: dark
```

### A Fuller Example

```yaml title="raffi.yaml"
version: 1

general:
  theme: dark
  font_size: 20
  main_view: [launchers, windows, browser_tabs, system, clipboard]

addons:
  apps:
    enabled: true
  system:
    trigger: power
  web_searches:
    - name: Google
      keyword: g
      url: "https://google.com/search?q={query}"
  script_filters:
    - name: Timezones
      keyword: tz
      command: batz
      args: ["-j"]
```

`apps` keeps installed applications in the list once you have entries of
your own; without any entries they are listed anyway.

## launchers.yaml

`launchers.yaml` is a mapping of names to [custom entries](../entries/):

```yaml title="launchers.yaml"
firefox_private:
  binary: firefox
  args: [--private-window]
  icon: firefox
  description: Firefox private window

backup:
  script: |
    rsync -a ~/Documents /mnt/backup/
    notify-send "Raffi" "Backup done"
  icon: drive-harddisk
  description: Back up my documents
```

Raffi reads `launchers.yaml` when `raffi.yaml` is missing or has no `launchers:` section of its own. If `raffi.yaml` does define entries, those win and `launchers.yaml` is ignored with a warning.

### Entries Inside raffi.yaml

A single file still works. Put the entries under a `launchers:` key in `raffi.yaml`, indented one level. The entry snippets in these docs are written for `launchers.yaml`; to use one in `raffi.yaml`, nest it under `launchers:`:

```yaml title="raffi.yaml"
version: 1

launchers:
  firefox_private:
    binary: firefox
    args: [--private-window]
    icon: firefox
```

## Path Expansion

Most configuration fields support path expansion:

- `~/` expands to your home directory
- `${VAR}` expands to environment variable values
- Unset variables expand to empty strings

```yaml title="launchers.yaml"
myapp:
  binary: ${HOME}/bin/myapp
  args: ["${XDG_DATA_HOME}/files", "~/Documents"]
  icon: ~/icons/myapp.png
  ifexist: ~/bin/myapp
```

<Aside type="note">
Path expansion is **not** applied to script content (`script` field). Only use it for paths, binaries, icons, and arguments.
</Aside>
